## What solved the connection problem

The old procedure repeatedly drew paths near decorative arches or across existing geometry. Visual proximity was mistaken for a genuine gate connection.

The successful procedure was:

1. Select the ride's **Connect Entrance to Path** action.
2. Select **Classic Paths** in queue mode, not the Customize Brush icon.
3. Locate the actual small white gate attachment marker. Seed one short classic segment whose preview originates at that marker.
4. Extend the attached queue outward with short, inspectable segments. Switch to Line Builder only after that first attached segment exists.
5. Anchor at the built queue endpoint and merge into the edge of the main guest path. Do not draw a queue across the main path and assume a crossing is a junction.
6. For the exit, change to **normal Guest Path**, seed a segment at the actual exit marker, and create a separate return loop into the plaza. The wheel's exit loop uses a five-meter guest path.
7. Confirm the accessibility checklist disappears, open the ride, and inspect real guests and ride statistics. An OPEN label alone is not sufficient evidence.

The existing decorative scenery was not accepted as a substitute for path connectivity. No ride warnings were dismissed to manufacture a passing result.
